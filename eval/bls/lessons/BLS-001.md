# BLS-001: Commodity discovery completes but calculation is deferred

**Status:** Resolved — evaluation-design correction; residual model failure documented
**Classification:** Evaluation workflow / simulated-user behavior
**Models:** `gpt-5.4-gov`, `gpt-5.6-luna-gov`

### BLUF: Problem, Mitigation, and Effect

**Problem:** The initial evaluation revealed that both GPT-5.4 and GPT-5.6 correctly identified the required PPI series and weights but stopped to request user confirmation rather than completing the escalation calculation. The evaluation's simulated user did not support this confirmation step, causing otherwise appropriate agent behavior to fail grading.

**Mitigation:** Updated the `commodity-series-selection` simulated user to approve a correctly proposed basket, allowing the agent to proceed through validation and calculation. No production MCP tooling or numerical oracles were changed.

**Effect:** Following the correction, GPT-5.4 passed 3 of 4 evaluation episodes (75%), while GPT-5.6 passed 3 of 3 (100%). Combined, 6 of 7 episodes passed (85.7%). The remaining GPT-5.4 failure involved selection of a narrower PPI series without the required historical observation, indicating a separate series-selection and recovery issue.

**Conclusion:** BLS-001 is resolved as an evaluation-design defect. The mitigation enabled successful completion of the intended workflow and exposed a distinct failure requiring further investigation. Because the evaluation changed, these results do not establish a measurable improvement in production MCP performance.

## 1. Original observed behavior

The original GPT-5.4 evaluation correctly identified the three required PPI series and associated weights.

The agent performed six catalog searches and three hierarchy lookups.

Rather than proceeding to specification validation and calculation, the agent requested confirmation of the proposed basket and periods.

The evaluation ended without a source-backed calculation because the simulated user did not provide a subsequent confirmation.

The original failure did not establish that the MCP server was defective.

## 2. Root-cause analysis

The original evaluation expected completion of the calculation but did not adequately support the confirmation interaction initiated by the agent.

The agent's request for confirmation was consistent with a cautious workflow for selecting economic indexes.

The mismatch was between the agent's confirmation behavior and the simulated-user workflow.

**Root cause classification:** Evaluation-design deficiency.

The original observation did not justify changing production MCP calculation behavior.

## 8. Regression risks

The evaluation correction introduces several risks requiring protection:

1. The simulated user might approve an incorrect basket.
2. Confirmation handling might inadvertently bypass validation.
3. A model might substitute a different series after approval.
4. The model might repeatedly request confirmation without progressing.
5. Changes to simulated-user behavior might affect evaluation comparability.

The existing numerical oracle and process checks should remain unchanged.

## 9. Comparability limitation
