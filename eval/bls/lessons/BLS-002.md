## BLUF: Problem, Mitigation, and Effect

**Problem:** Commodity-selection episodes included redundant searches and zero-result commodity queries. The catalog uses a literal substring match and exposes a constant `match_score=1.0`, limiting relevance feedback. Observed call counts were 8 for GPT-5.4 and 17 for GPT-5.6 in earlier investigations; those counts are diagnostic, not hard failures.

**Mitigation:** Proposed narrow production change: treat hyphens and spaces equivalently in literal catalog search, with a deterministic store-level regression test. No evaluation scenarios, graders, numerical oracles, or model prompts are changed. Relevance ranking and synonyms are deliberately out of scope until independently benchmarked.

**Effect:** Not yet measured. Run focused tests and comparable model evaluations after applying the patch. Do not attribute any improvement to the patch before collecting post-change evidence.

**Conclusion:** Open pending verification. Search normalization is a defensible limited regression protection, but the available episode data do not establish that it alone resolves semantic zero-result searches or model inefficiency.

## 1. Original observed behavior

Original BLS-002 investigation recorded zero-result searches for relevant commodity descriptions and repeated discovery calls. In the current repository, `src/bls_mcp/storage/store.py` uses `strpos(lower(concat_ws(...)), lower(?)) > 0`; `src/bls_mcp/services/series_catalog.py` assigns the same score to every textual hit. This patch targets only punctuation normalization.

## 2. Root-cause analysis

**Confirmed:** Literal substring search treats `CPI-U` and `CPI U` differently; all textual hits receive the same service-level score.
**Hypotheses:** Synonyms and poor ranking contribute to repeated model searches. Not proven by this focused change.
**Classification:** Narrow production search robustness gap, with broader relevance investigation still open.

## 3. Mitigation or proposed intervention

- Normalize hyphen to space on both sides of the SQL substring comparison.
- Add a deterministic regression test using the existing CPI-U fixture.
- Preserve parameter binding, literal matching, pagination, and the frozen nine-case suite.
- Do not add synonyms, ranking, fuzzy search, or new evaluation cases in this update.

## 5. Residual failures and follow-up

A GPT-5.4 episode selected a narrower gypsum series without the requested historical observation and failed to recover. This patch does not address availability checks or series suitability. Queue additional evaluation coverage only after the production change is verified.

## 6. Regression risks

- Hyphen/space normalization may increase false-positive matches; compare result sets.
- Replacing punctuation can affect query selectivity and latency; measure both.
- Exact series-ID lookup and SQL parameterization must remain functional.
- The search API still exposes non-discriminating match scores; do not claim ranking improvement.
